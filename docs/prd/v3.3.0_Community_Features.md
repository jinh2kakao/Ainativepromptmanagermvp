# 제품 요구사항 문서 (PRD): 고객 지원 및 커뮤니티 시스템 (v3.3.0)

## 1. 개요 (Overview)
본 PRD는 사용자 경험 증대와 효율적인 운영 관리를 위해 **공지사항(Notice), FAQ, 1:1 문의(QnA)** 시스템을 구축하고, 누락되었던 **에이전트 모델 관리** 기능을 어드민 콘솔에 통합하는 것을 목표로 합니다.

이 업데이트를 통해 사용자는 서비스의 소식을 빠르게 접하고(Notice), 자주 묻는 질문을 통해 문제를 스스로 해결하며(FAQ), 해결되지 않는 문제는 관리자와 비실시간 채팅 형태의 게시판을 통해 소통(QnA)할 수 있습니다. 또한, 관리자는 이 모든 컨텐츠와 에이전트 모델 정보를 어드민 콘솔에서 통합 관리할 수 있게 됩니다.

## 2. 핵심 요구사항 (Key Requirements)

### 2.1. 공지사항 (Notice) 구현
**목표**: 서비스의 주요 업데이트, 점검, 이벤트 소식을 사용자에게 효과적으로 전달합니다.

*   **User Side (사용자)**
    *   **진입점**: `설정(Settings)` 메뉴 내 사이드바 또는 별도 탭에 '공지사항' 메뉴 추가.
    *   **기능**:
        *   공지사항 목록 조회 (제목, 작성일, 중요/고정 표시).
        *   공지사항 상세 조회 (제목, 내용, 작성일, 작성자).
        *   최신 공지사항이 있을 경우 설정 아이콘 등에 알림 표시(Optional, 추후 고도화).

*   **Admin Side (관리자)**
    *   **진입점**: `Admin Console > Notices`.
    *   **기능 (CRUD)**:
        *   **Create**: 제목, 본문(Rich Text or Markdown), 게시 여부, 상단 고정 여부 작성.
        *   **Read**: 공지사항 페이징 목록, 검색(제목/내용).
        *   **Update**: 내용 수정 및 게시 상태 변경.
        *   **Delete**: 공지사항 삭제 (Soft Delete 권장).

### 2.2. FAQ (자주 묻는 질문) 구현
**목표**: 사용자가 반복적으로 질문하는 내용을 정리하여 CS 리소스를 절감하고 사용자 편의를 돕습니다.

*   **User Side (사용자)**
    *   **진입점**: `설정(Settings)` 메뉴 내 '자주 묻는 질문' 또는 '도움말' 메뉴.
    *   **기능**:
        *   카테고리별 FAQ 목록 조회 (Accordion UI 권장 - 클릭 시 답변 확장).
        *   FAQ 검색 기능.

*   **Admin Side (관리자)**
    *   **진입점**: `Admin Console > FAQ`.
    *   **기능 (CRUD)**:
        *   **Create**: 질문(Question), 답변(Answer), 카테고리(예: 계정, 결제, 사용법).
        *   **Read**: FAQ 목록 관리.
        *   **Update**: 내용 수정.
        *   **Delete**: FAQ 삭제.

### 2.3. QnA (1:1 문의) 구현
**목표**: 사용자의 개별적인 문의사항을 비실시간 게시판 형태로 접수하고 처리합니다. 마치 채팅을 하는 듯한 UI로 친근감을 주되, 기술적으로는 게시글-댓글 구조를 가집니다.

*   **User Side (사용자)**
    *   **진입점**: `설정(Settings)` 메뉴 내 '1:1 문의' 또는 '고객센터'.
    *   **UI 개념**: **"Chat-like Thread UI"**
        *   사용자가 문의글을 작성하면 채팅방이 생성되는 느낌의 UI.
        *   관리자의 답변이 달리면 채팅 말풍선처럼 아래에 표시.
        *   사용자가 다시 대댓글을 달 수 있음 (Nested Comment).
    *   **기능**:
        *   내 문의 내역 목록 조회 (답변 대기/답변 완료 상태 표시).
        *   새 문의 작성 (제목, 내용, 카테고리).
        *   상세 대화 화면 (본문 + 댓글 타임라인).

*   **Admin Side (관리자)**
    *   **진입점**: `Admin Console > QnA` (CS 관리).
    *   **기능**:
        *   **문의 목록 (Inbox)**: '답변 대기' 상태인 문의 필터링 조회.
        *   **상세 및 답변**: 사용자 문의 내용 확인 및 댓글(답변) 작성.
        *   **상태 변경**: 답변 작성 시 자동으로 '답변 완료' 처리, 필요시 수동 상태 변경 (종료 등).
        *   **회원 정보 연동**: 문의 상세 화면에서 질문한 사용자의 기본 정보(이메일, 플랜 등) 바로 확인 가능 링크 또는 요약 카드 제공.

### 2.4. 에이전트 모델 관리 (Agent Model Management)
**목표**: 이전 PRD에서 누락된 AI 모델 메타데이터를 어드민에서 직접 관리하여 시스템의 확장성을 높입니다.

*   **Admin Side (관리자)**
    *   **진입점**: `Admin Console > System > AI Agents`.
    *   **기능 (CRUD)**:
        *   **Create/Add**: 모델 ID(예: `gpt-4o`, `claude-3-5-sonnet`), 표시 이름(Display Name), 제공사(Provider), 버전, 활성화 여부.
        *   **Read**: 등록된 모델 목록.
        *   **Update**: 표시 이름 수정, 일시 비활성화(Deprecated 처리).
        *   **Delete**: 삭제 (사용 중인 템플릿 참조 무결성 주의 - Soft Delete 권장).

## 3. 기술적 고려사항 (Technical Considerations)

### 3.1. 데이터베이스 스키마 설계 (PostgreSQL)

*   **Notice 테이블**
    *   `id` (UUID), `title`, `content` (Text), `is_published` (Bool), `is_pinned` (Bool), `created_at`, `updated_at`, `author_id` (FK).
*   **FAQ 테이블**
    *   `id` (UUID), `category` (String/Enum), `question`, `answer` (Text), `display_order` (Int).
*   **Inquiry (QnA) 테이블**
    *   `id` (UUID), `user_id` (FK), `title`, `status` (Enum: `PENDING`, `ANSWERED`, `CLOSED`), `created_at`, `updated_at`.
*   **InquiryComment (QnA 댓글) 테이블**
    *   `id` (UUID), `inquiry_id` (FK), `author_id` (FK), `content`, `created_at`, `is_staff_reply` (Bool - UI 구분용).
*   **AgentModel 테이블**
    *   `id` (UUID), `model_key` (Unique Str), `name`, `provider`, `is_active` (Bool).

### 3.2. 백엔드 (Backend API)
*   **Notices**: `/api/notices` (Public Read), `/api/admin/notices` (CRUD).
*   **FAQs**: `/api/faqs` (Public Read), `/api/admin/faqs` (CRUD).
*   **QnA**:
    *   POST `/api/inquiries` (문의 등록)
    *   GET `/api/inquiries` (내 문의 목록)
    *   GET `/api/inquiries/{id}` (상세 + 댓글 목록)
    *   POST `/api/inquiries/{id}/comments` (추가 댓글 작성)
    *   `/api/admin/inquiries/...` (전체 조회 및 답변 작성)
*   **Agents**: `/api/admin/agents` (CRUD), `/api/agents` (Public List - for dropdowns).

### 3.3. 프론트엔드 (Frontend)
*   **Settings Layout**: 사이드바 메뉴 확장 (공지사항, FAQ, 1:1 문의).
*   **Chat UI Component**: QnA 상세 화면을 위한 말풍선 스타일 컴포넌트 (`Bubble`, `Thread`).
*   **Admin Layout**: 메뉴 구조 재정비 (Community 섹션 하위에 Notice, FAQ, QnA 배치 / System 섹션 하위에 AI Agents 배치).

## 4. 디자인/UX 가이드
*   **Settings**: 기존 설정 화면의 톤앤매너 유지.
*   **QnA**:
    *   **카카오톡/슬랙**과 유사한 친숙한 대화형 인터페이스 차용.
    *   단, 실시간 웹소켓 채팅이 아니므로 "입력 중..." 표시 등은 불필요하며, 댓글 전송 시 "답변이 등록되면 알림을 보내드립니다(기획 예정)" 등의 피드백 제공.
    *   CS 담당자 답변은 배경색이나 프로필을 다르게 하여 명확히 구분 (예: 짙은 배경, 브랜드 로고 프로필).

## 5. 영향도 분석 (Impact Analysis)
*   **DB 마이그레이션**: 신규 테이블 4~5개 추가 필요.
*   **보안**: QnA는 민감한 개인정보가 포함될 수 있으므로 본인 및 관리자만 접근 가능하도록 엄격한 ACL 적용 (Row Level Security 또는 API 레벨 검증).
*   **확장성**: 추후 'Agent Model' 테이블은 템플릿의 'Applicable Agents' 기능과 FK로 연결될 수 있음 (현재는 문자열 매칭일 수 있으나 점진적 마이그레이션 고려).
