# 제품 요구사항 문서 (PRD): 이메일 인증 및 회원 등급 개편 (v3.1.0)

## 1. 개요 (Introduction)
이 문서는 회원가입 시 실제 이메일 인증을 도입하고, 회원 등급별 제한 사항을 재구성하기 위한 요구사항을 정의합니다. 특히 **Enterprise 등급**을 신설하여 팀 협업 기능을 제공하고, 각 등급별로 세분화된 AI 기능 사용 제한을 적용합니다.

## 2. 요구사항 (Requirements)

### 2.1. 실제 이메일 인증 (Real Email Verification)
**목표**: 현재의 Mockup(임시) 인증 방식을 제거하고, 실제 이메일 기반의 인증 시스템으로 교체합니다.

**변경 후 상태 (To-Be)**:
- **트리거**: 사용자가 회원가입 시 이메일 인증을 요청합니다.
- **동작**: 백엔드에서 6자리 무작위 코드를 생성하고, SMTP 서비스(Gmail 등)를 통해 발송합니다.
- **보안**: 다중 요청 방지(Rate Limiting) 및 코드의 일회성/만료 처리를 적용합니다.

### 2.2. 회원 등급 개편 (Membership Tier Revamp)
**목표**: "Free", "Pro", "Enterprise" 3단계로 등급을 구분하고, AI 기능 사용량 및 팀 기능을 차별화합니다.

**등급 정의**:
| 기능 | 무료 (Basic) | 유료 (Pro) | 기업 (Enterprise) |
| :--- | :--- | :--- | :--- |
| **프롬프트 생성** | **무제한** | **무제한** | **무제한** |
| **AI 최적화/평가** | **5회 / 일** | **40회 / 일** | **80회 / 일** |
| **팀 협업** | 지원 안 함 | 지원 안 함 | **팀 생성 및 멤버 초대** |

**기술적 영향**:
- **사용량 제한**: `OptimizationJob` 및 `PromptEvaluation` 실행 시 유저 등급에 따라 일일 한도(5/40/80)를 체크합니다.
- **팀 기능**: `Team` 생성 및 `TeamMember` 초대는 오직 `ENTERPRISE` 등급 유저만 가능하도록 백엔드 권한을 제어합니다.

### 2.3. 업그레이드 모달 개편 (Upgrade Modal Update)
**목표**: 3단계 등급 정책을 UI에 반영합니다.

**변경 사항**:
- `PricingModal.tsx` 디자인을 수정하여 3가지 플랜(또는 Enterprise 별도 강조)을 노출합니다.
- **Basic**: "개인용", "AI 기능 체험 (일 5회)"
- **Pro**: "전문가용", "AI 기능 활용 (일 40회)"
- **Enterprise**: "조직용", "AI 기능 극대화 (일 80회)", "팀 워크스페이스 제공"

## 3. 구현 계획 (Implementation Plan)

### 1단계: 백엔드 (Backend)
1.  **Email Verification**: SMTP 기반 인증 코드 발송/검증 API 구현.
2.  **Tier Logic**: `UserType`에 따른 Limit 상수 정의 (`LIMIT_FREE=5`, `LIMIT_PRO=40`, `LIMIT_ENT=80`).
3.  **Permission Check**: 팀 생성 API 호출 시 `current_user.user_type == ENTERPRISE` 체크 추가.

### 2단계: 프론트엔드 (Frontend)
1.  **Auth**: 회원가입 시 이메일 인증 API 연동.
2.  **Pricing Modal**: Enterprise 플랜 카드 추가 및 문구 업데이트.
3.  **Limit Warning**: 제한 도달 모달에서 "Pro로 업그레이드"(무료일 때) 또는 "Enterprise 문의"(Pro일 때) 등으로 분기 처리 고려.

## 4. 가정 및 결정 사항 (Assumptions & Decisions)
- **Enterprise 업그레이드**: MVP 단계에서는 결제 모듈 연동 대신 "문의하기" 또는 Pro와 동일한 결제 흐름(금액 차이)을 따를 수 있으나, 일단 UI 상으로만 구분합니다. (구체적 결제 로직은 별도 논의 필요)
- **기존 Pro 유저**: 기존 Pro 유저도 새로운 제한(40회)을 적용받습니다.
