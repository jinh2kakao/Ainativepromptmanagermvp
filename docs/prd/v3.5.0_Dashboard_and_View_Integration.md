## 1. 개요 (Overview)

### 1.1 배경 및 목적
현재 사용 가능한 피드백 분석 결과, **사용자의 초기 진입 경험(Onboarding)**과 **작업 효율성(Usability)** 개선이 시급합니다.
1.  **View Fragmentation:** 사용자가 List View와 Kanban View를 상황에 따라 자유롭게 전환하지 못하고 고정된 뷰를 사용하여 불편함을 겪고 있습니다.
2.  **Empty Dashboard:** 초기 대시보드가 단순히 "빈 프롬프트 리스트"로 노출되어, 신규 사용자나 Guest에게 플랫폼의 가치를 즉각적으로 전달하지 못하고 있습니다.

### 1.2 목표 (Goals)
-   **User Control:** 사용자가 선호하는 방식(List/Kanban)으로 프롬프트를 조회할 수 있는 제어권 부여.
-   **Discovery:** 대시보드에서 고품질 템플릿을 즉시 노출하여 "Create First Prompt" 전환율 증대.
-   **Personalization:** 기존 사용자에게는 "최근 사용한 템플릿/작업"을 노출하여 작업 연속성 보장.

## 2. 기능 요구사항 (Feature Specifications)

### 2.1 Feature A: 프롬프트 뷰 통합 (Unified View Toggle)

#### 2.1.1 기능 정의
사용자가 프롬프트 목록을 조회할 때 **List(목록형)**와 **Kanban(보드형)** 중 원하는 뷰 모드를 토글 버튼으로 전환할 수 있습니다.

#### 2.1.2 UI/UX 상세
-   **위치:** "My Prompts" 섹션 헤더 우측 상단 (검색바 옆).
-   **컴포넌트:** `Segmented Control` 또는 `Toggle Group` 스타일.
    -   `[List Icon]` | `[Kanban Icon]`
-   **상태 유지 (Persistence):**
    -   사용자가 선택한 뷰 모드는 브라우저(`localStorage`)에 저장되어야 합니다.
    -   재방문 시 마지막으로 선택한 뷰가 유지되어야 합니다.
-   **반응형 동작:**
    -   Mobile 환경에서는 화면 너비 제약으로 인해 강제 **List View**로 고정하거나, Kanban을 **Vertical Stack**으로 변형합니다. (초기 MVP는 List 강제 권장)

#### 2.1.3 User Story
> "나는 많은 프롬프트를 한눈에 훑어보고 싶을 때는 **List View**를 쓰고, 카테고리별 분포를 보고 싶을 때는 **Kanban View**를 쓰고 싶다."

### 2.2 Feature B: 대시보드 템플릿 디스커버리 (Dashboard Discovery)

#### 2.2.1 기능 정의
초기 진입 화면(Dashboard)을 단순 프로젝트 목록에서 **"작업 시작을 위한 허브"**로 재정의합니다.

#### 2.2.2 섹션 구성 및 로직

**A. 상단: Welcome & Personalization (로그인 유저 전용)**
-   **타이틀:** "Welcome back, {User}!"
-   **최근 사용한 템플릿 (Recently Used Templates):**
    -   최대 4개 노출.
    -   카드 형태:
        -   **이미지:** 템플릿에 `preview_image`가 있을 경우 상단에 노출.
        -   **정보:** 템플릿 명, 간단 설명, 바로가기 버튼.
    -   데이터가 없을 경우 숨김 처리.

**B. 중단: Popular Templates (전체 사용자)**
-   **타이틀:** "🔥 Popular Templates"
-   **로직:**
    -   가장 많이 복사/실행된 템플릿 Top 6.
    -   초기 데이터 부족 시 "Admin 추천 템플릿"으로 하드코딩 또는 `is_featured` 플래그 사용.
    -   **UI:** 썸네일 이미지가 포함된 카드 그리드 형태.

**C. 하단: Category Shortcuts**
-   **타이틀:** "Browse by Category"
-   **UI:** 주요 카테고리(개발, 마케팅, 디자인 등) 아이콘 그리드. 클릭 시 해당 카테고리 필터가 적용된 템플릿 페이지로 이동.

**D. 기존: My Prompts**
-   기존 프롬프트 리스트는 하단으로 배치하되, 데이터가 있을 경우 상위로 올리는 **"스마트 정렬"** 고려 (MVP에서는 하단 고정).

#### 2.2.3 Data Model Requirements
템플릿의 "인기"와 "최근 사용"을 추적하기 위한 데이터 모델 확장이 필요합니다.

```sql
CREATE TABLE template_usage (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    user_id UUID REFERENCES users(id), -- Guest일 경우 Nullable 고려 or Guest ID 저장
    template_id UUID REFERENCES prompt_templates(id),
    action_type TEXT NOT NULL, -- 'copy', 'view', 'run'
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 템플릿 테이블 확장
ALTER TABLE prompt_templates ADD COLUMN preview_image_url TEXT;
```

### 2.3 Feature C: 템플릿 상세 페이지 (Dedicated Template Detail)

#### 2.3.1 기능 정의
기존 프롬프트 상세 페이지와 분리된, **템플릿 전용 상세 페이지**를 제공합니다. 사용자는 템플릿의 내용을 "읽기 전용"으로 확인하고, "사용하기(Use/Copy)" 결정을 내릴 수 있습니다.

#### 2.3.2 UI 구성
-   **URL:** `/templates/[id]`
-   **Header:**
    -   템플릿 제목, 작성자(Admin/User), 카테고리 뱃지.
    -   **Preview Image:** 상단 히어로 섹션 또는 우측 사이드에 크게 배치.
-   **Content:**
    -   템플릿 설명 (Description).
    -   프롬프트 내용 (Read-only, 변수 강조).
-   **Actions:**
    -   `[Use this Template]` (Primary): 내 프롬프트로 복사하여 수정 화면 이동.
    -   `[Preview In Editor]` (Secondary): 비로그인 시 에디터 체험.

#### 2.3.3 User Flow
1.  대시보드 또는 템플릿 리스트에서 **Template Card** 클릭.
2.  `/templates/[id]` 상세 페이지에서 내용 및 에이전트 정보 확인.
3.  **Use this Template** 버튼 클릭.
4.  `/prompts/new?templateId=[id]` 로 이동.
5.  **New Prompt Page** 로딩 시:
    -   `templateId`로 템플릿 상세 정보 Fetch.
    -   Form 초기화: 제목, 내용, 카테고리/직무, **적용 가능한 에이전트(Job Functions)** 자동 선택.
    -   사용자는 바로 '저장' 또는 '수정' 가능 상태 진입.

## 4. 기술 아키텍처 및 구현 계획

### 4.1 Frontend (Next.js)
-   **Store:** `useUIStore`에 `viewMode` ('list' | 'kanban') 추가.
-   **Component:**
    -   `ViewToggle.tsx`: 공통 UI 컴포넌트.
    -   `DashboardTemplates.tsx`: 템플릿 섹션 컨테이너.
    -   `TemplateCard.tsx`: 대시보드용 미니 카드.
-   **Page:** `src/app/page.tsx` 레이아웃 전면 수정.

### 4.2 Backend (FastAPI)
-   **Schema:** `TemplateUsage` 모델 추가 (SQLModel).
-   **API:**
    -   `GET /api/templates/stats/popular`: 인기 템플릿 집계.
    -   `GET /api/templates/stats/recent`: 내 최근 사용 이력.
    -   `POST /api/templates/{id}/track`: 사용 이력 저장 로직.

### 4.3 Implementation Steps

1.  **Phase 1 (View Integration):**
    -   `uiStore` 업데이트.
    -   `PromptListContainer` 수정 및 토글 UI 부착 (우선순위 높음, Quick Win).
2.  **Phase 2 (Templates Data):**
    -   DB Migration & Backend API 구현.
3.  **Phase 3 (Dashboard UI):**
    -   Frontend 대시보드 레이아웃 개편.
    -   템플릿 섹션 연동.

## 5. 성공 지표 (Success Metrics)
-   **템플릿 사용률:** 대시보드 개편 후 템플릿 클릭/사용 횟수 30% 증가.
-   **초기 이탈률:** Guest 사용자의 초기 이탈률 10% 감소 (Empty state 제거 효과).
-   **기능 활용:** 사용자의 20% 이상이 뷰 토글 기능을 적극적(주 1회 이상 전환)으로 사용.
