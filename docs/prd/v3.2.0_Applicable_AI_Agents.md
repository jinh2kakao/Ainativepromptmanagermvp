# 제품 요구사항 문서 (PRD): 템플릿 별 적용 가능한 AI 에이전트 설정 (v3.2.0)

## 1. 개요 (Overview)
본 PRD는 프롬프트 템플릿 시스템에 "적용 가능한 AI 에이전트(Applicable AI Agents)" 속성을 추가하고, 이를 관리자 템플릿 관리부터 사용자 템플릿 적용, 그리고 AI 최적화/평가 로직까지 전반적으로 반영하기 위한 요구사항을 정의합니다.

목표는 사용자가 특정 AI 모델(예: GPT-4, Claude-3.5-Sonnet, Gemini-1.5-Pro)에 최적화된 프롬프트 템플릿을 식별하고 활용할 수 있도록 돕고, 시스템이 이를 인지하여 더 정교한 최적화 결과를 제공하는 것입니다.

## 2. 핵심 요구사항 (Key Requirements)

### 2.1. Admin Console: 템플릿 관리
**목표**: 관리자가 템플릿을 생성하거나 수정할 때, 이 템플릿이 어떤 AI 에이전트에 적합한지 지정할 수 있어야 합니다.

- **UI 변경**:
  - `Admin > Templates > Edit/Create` 페이지에 "적용 가능한 AI 에이전트" 선택 입력 필드 추가.
  - **다중 선택 가능**: Chip 형태의 멀티 셀렉트 UI 제공 (예: `['GPT-4', 'Claude-3.5']`).
  - **프리셋 제공**: 시스템에 정의된 AI Agent/Model 목록을 불러와 선택지로 제공.
- **데이터 처리**:
  - 입력된 에이전트 목록을 `PromptTemplate` DB 테이블에 저장.

### 2.2. User: 템플릿 사용 (적용)
**목표**: 사용자가 템플릿을 선택하거나 적용할 때, 해당 정보를 확인하고 프롬프트 작성에 반영할 수 있어야 합니다.

- **템플릿 선택 시**:
  - 템플릿 목록/카드에서 "Recommended for: GPT-4, Claude..." 와 같이 배지나 텍스트로 표시.
- **템플릿 적용 로직**:
  - 사용자가 템플릿 선택 후 "적용(Apply)"하면, 템플릿에 설정된 `applicable_agents` 값이 현재 작성 중인 프롬프트의 `applicable_agents` 필드로 복사됨.
  - 기존값이 있을 경우: 템플릿 값으로 덮어쓰기 (사용자 확인 옵션 고려 가능하나 초기엔 덮어쓰기).

### 2.3. User: 설계 평가 (Design Eval)
**목표**: 프롬프트 설계 평가(Evaluation) 기능이 수행될 때, 설정된 "적용 가능한 AI 에이전트" 정보를 맥락으로 활용합니다.

- **평가 로직**:
  - 평가자(Judge Model)에게 "이 프롬프트는 [GPT-4] 사용을 목적으로 작성되었습니다"라는 맥락을 주입.
  - 평가 기준에 "모델 특이성 준수" 항목을 은유적으로 포함 (예: Claude의 경우 XML 태그 사용 권장 등).

### 2.4. User: AI 최적화 (Optimization)
**목표**: AI가 프롬프트를 최적화(Rewrite)해줄 때, 타겟 에이전트의 특성을 반영합니다.

- **최적화 프롬프트(Meta-Prompt) 수정**:
  - Optimizer에게 전달되는 입력 프롬프트에 `Target Models: [GPT-4, Gemini]` 정보를 포함.
  - **지시사항 추가**: "지정된 타겟 모델들이 잘 이해하고 성능을 낼 수 있는 구조(예: Chain-of-Thought, Delimiters 등)를 우선적으로 적용하시오."

## 3. 기술적 고려사항 (Technical Considerations)

### 3.1. 데이터베이스 스키마
- **Table**: `PromptTemplate`
- **Field**: `applicable_agents` (Type: `JSON` or `ARRAY<VARCHAR>`) 추가.
  - 기존 `Prompt` 테이블에는 이미 유사 필드가 존재할 수 있으나 확인 필요 (없다면 `Prompt` 테이블에도 추가).

### 3.2. 백엔드 (Backend)
- **API Models**: `PromptTemplateCreate`, `PromptTemplateUpdate`, `PromptTemplateRead` 스키마에 필드 추가.
- **Optimization Worker**: `dspy` 시그니처(`OptimizePromptSignature`)에 `target_agents` 입력 필드 추가 및 로직 반영.

### 3.3. 프론트엔드 (Frontend)
- **Selectable Agents UI**: 기존에 개발된 "Selectable AI Agents" 컴포넌트를 Admin Template form에 재사용.
- **Template Apply**: `applyTemplate` 함수에서 `applicable_agents` 데이터 핸들링 로직 추가.

## 4. 디자인/UX 가이드
- **Visual**: 에이전트 이름은 로고와 함께 칩(Chip) 형태로 시각화하여 프리미엄한 느낌 전달.
- **Consistency**: 사용자 프롬프트 수정 화면의 에이전트 선택 UI와 템플릿 관리 화면의 UI 통일.

## 5. 영향도 분석 (Impact Analysis)
- **기존 데이터**: 기존 템플릿의 경우 해당 필드는 `null` 또는 `[]` (Empty)로 마이그레이션.
- **호환성**: 템플릿 버전 관리나 하위 호환성에 문제없음 (Optional 필드).
