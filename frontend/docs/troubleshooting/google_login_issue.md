# 구글 로그인 에러 원인 분석 보고서

## 1. 에러 개요
- **에러 메시지**: `403 disallowed_useragent` (액세스 차단됨)
- **발생 환경**: 특정 모바일 앱 내부의 브라우저 (In-App Browser/WebView)
- **차단 주체**: Google OAuth 서버

## 2. 원인 분석
이 에러는 Google의 **보안 브라우저 사용 정책(Secure Browser Usage Policy)**에 의해 발생합니다.
Google은 2016년부터 보안상의 이유(피싱 방지, 중간자 공격 방지)로 **임베디드 웹뷰(WebView)에서의 OAuth 인증 요청을 차단**하고 있습니다.

### 상세 원인
1.  **User-Agent 감지**: 구글 인증 서버는 요청을 보낸 브라우저의 User-Agent를 검사합니다.
2.  **WebView 식별**: 특정 앱(카카오톡, 네이버 앱, 또는 사용자가 직접 만든 웹뷰 래퍼 앱 등) 내에서 실행되는 브라우저가 "완전한 브라우저(Chrome, Safari 등)"가 아닌 "임베디드 웹뷰"로 식별될 경우 로그인을 차단합니다.
3.  **n8nAppWeb**: 스크린샷에 표시된 `n8nAppWeb`은 Google Cloud Console에 등록된 OAuth 클라이언트의 이름(프로젝트 이름)입니다.

## 3. 해결 방안

### 방법 A: 사용자 대응 (가장 확실함)
사용자가 현재 보고 있는 인앱 브라우저 대신 **시스템 기본 브라우저(Chrome, Safari, 삼성 인터넷 등)**에서 해당 페이지를 열도록 유도해야 합니다.
- 대부분의 인앱 브라우저(카카오톡 등)는 우측 하단/상단 메뉴에 "다른 브라우저로 열기" 기능을 제공합니다.

### 방법 B: 개발 대응 (코드 수정)
웹 애플리케이션 레벨에서 인앱 브라우저를 감지하여 강제로 외부 브라우저를 띄우거나 안내 메시지를 보여주는 코드를 추가할 수 있습니다.

**1. Supabase OAuth 옵션 조정 (일부 환경에서 유효)**
`redirectTo` 옵션을 사용하여 팝업 방식이 아닌 리다이렉트 방식을 명확히 지정하거나, `skipBrowserRedirect`를 사용하여 URL을 받아 직접 제어할 수 있으나, User-Agent 차단 자체를 우회하기는 어렵습니다.

**2. 인앱 브라우저 감지 및 우회 (권장)**
사용자가 인앱 브라우저로 접속했을 때, 구글 로그인을 시도하면 "보안을 위해 외부 브라우저에서 실행해주세요"라는 안내를 띄우거나, 자동으로 외부 브라우저 호출을 시도하는 스크립트를 적용할 수 있습니다.

```typescript
// 예시: 구글 로그인 버튼 클릭 시
const handleGoogleLogin = async () => {
    const userAgent = navigator.userAgent.toLowerCase();
    // 카카오톡, 라인 등 인앱 브라우저 감지
    if (userAgent.includes('kakao') || userAgent.includes('line')) { 
        alert('구글 로그인은 보안 정책상 기본 브라우저(Chrome/Safari)에서 진행해야 합니다. 우측 메뉴의 "다른 브라우저로 열기"를 이용해주세요.');
        return;
    }
    // ... 기존 로그인 로직
};
```

## 4. 결론
이 문제는 애플리케이션의 버그가 아니라 **Google의 강력한 보안 정책**에 의한 정상적인 차단 동작입니다. 따라서 코드로 "차단을 뚫는" 것은 불가능하며, **"안전한 브라우저(시스템 브라우저)로 진입시키는" 흐름**을 만들어야 합니다.
